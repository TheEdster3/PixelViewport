Method, raw results, and limitations

Measured

Seeded synthetic buffers, preallocated destination, and sorted wall-clock samples. The p95 includes scheduler noise; competing processes were not controlled.

Not measured

Acquisition, UI scheduling, bitmap upload, composition, scan-out, or overlays. The alpha uses UI-thread CPU conversion. Sustained 4K, GPU, and Linux performance remain unverified.

Before you integrate

SCOPE & READINESS
Does PixelViewport acquire images or run vision algorithms?

No. It sits between your existing camera or vision pipeline and the application UI. Keep your acquisition SDK, processing library, and hardware choices.

Which platforms are ready to evaluate?

The current solution builds and its samples launch on Windows. Avalonia is the cross-platform adapter, but Linux and embedded hardware have not been validated. WPF is a future adapter, not part of this alpha.

Is there a production GPU renderer in this release?

No. The current Avalonia path performs CPU conversion on the UI thread and presents a WriteableBitmap. Production GPU/zero-copy rendering is commercial roadmap work.
