04 / GET YOUR FRAMES ON SCREEN

Small integration surface.
Explicit lifetime.

Start from the source or the alpha release packages. The optional OpenCvSharp adapter keeps your core contracts vendor-neutral.

// Memory stays leased until the viewport releases it.
using PixelViewport.Imaging;

var frame = PixelFrame.Wrap(
    buffer, width, height, stride,
    ImagePixelFormat.Gray16LittleEndian,
    sequence, DateTimeOffset.UtcNow, lease);

viewport.SubmitFrame(frame);
// Ownership transfers. Don't reuse the buffer yet.
using PixelViewport.OpenCvSharp;

Mat result = AcquireOrProcessFrame();
viewport.SubmitFrame(
    MatFrameAdapter.TakeOwnership(result));

// The viewport now owns and eventually disposes Mat.
// Use Copy(result) if the caller needs to retain it.
// Your application supplies the native OpenCV runtime.

Does PixelViewport acquire images or run vision algorithms?

No. It sits between your existing camera or vision pipeline and the application UI. Keep your acquisition SDK, processing library, and hardware choices.

Which platforms are ready to evaluate?

The current solution builds and its samples launch on Windows. Avalonia is the cross-platform adapter, but Linux and embedded hardware have not been validated. WPF is a future adapter, not part of this alpha.

Is there a production GPU renderer in this release?

No. The current Avalonia path performs CPU conversion on the UI thread and presents a WriteableBitmap. Production GPU/zero-copy rendering is commercial roadmap work.
