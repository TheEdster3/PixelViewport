INTEGRATION GUIDE / 02 · WINDOWS ALPHA

Sixteen-bit data.
Eight-bit display.
Keep the distinction.

A displayed gray level is not the raw sensor value. PixelViewport's alpha keeps the original frame leased for inspection while creating a BGRA32 representation for the Avalonia bitmap.

1. Describe the actual buffer

Gray16LittleEndian means an unpacked unsigned 16-bit intensity per pixel, stored low byte first. The stride is bytes per row—not pixels—and may include padding.

using System.Buffers.Binary;
using PixelViewport.Imaging;

const int width = 640, height = 480;
int stride = width * 2;
byte[] pixels = new byte[stride * height];

for (int y = 0; y < height; y++)
    for (int x = 0; x < width; x++)
        BinaryPrimitives.WriteUInt16LittleEndian(
            pixels.AsSpan(y * stride + x * 2, 2),
            (ushort)(x * 65535 / (width - 1)));

var frame = PixelFrame.Wrap(
    pixels, width, height, stride,
    ImagePixelFormat.Gray16LittleEndian);

viewport.SubmitFrame(frame);
// Do not mutate pixels until PixelViewport releases the frame.

This snippet goes inside your Avalonia application's setup or producer code with an existing PixelViewport.Avalonia.ImageViewport. For a running application shell, start from the VisionDemo sample.

2. Use a lease—or make a copy

A camera SDK's buffer may be returned to a pool immediately after its callback. Passing that memory without retaining its lifetime is unsafe. Supply an appropriate IDisposable lease to PixelFrame.Wrap, or copy before the callback returns:

var frame = PixelFrame.CopyFrom(
    callbackBytes, width, height, stride,
    ImagePixelFormat.Gray16LittleEndian,
    sequence, DateTimeOffset.UtcNow);

viewport.SubmitFrame(frame);

callbackBytes, dimensions, and sequence come from your acquisition code. Copying allocates an owned pooled buffer and decouples its lifetime from the camera callback. Wrapping a native pointer uses PixelFrame.WrapUnmanaged and has the same lifetime requirement.

3. Inspect the original intensity

viewport.ImagePointerMoved += (_, e) =>
{
    if (e.IsInsideImage && e.Sample is { } sample)
        System.Diagnostics.Debug.WriteLine(
            $"Raw intensity: {sample.Intensity}; " +
            $"bit depth: {sample.BitDepth}");
};

For Gray16, inspection returns values from 0 to 65535 with bit depth 16. Wheel zoom and pan change the screen transform, not the underlying pixel coordinate system.

4. Understand today's display mapping

The Community converter uses the high byte: displayGray = rawIntensity >> 8. An intensity of 32768 becomes a displayed gray value of 128. The original value remains available for inspection.

That linear full-range mapping is deliberately simple. A signal occupying only a narrow part of the 16-bit range may look nearly black. Adjustable window/level, calibrated measurement, richer LUTs, and packed camera formats are not implemented in this alpha.

The website's Gray16 playground is a synthetic JavaScript illustration. The published CPU conversion numbers come from the .NET probe; neither measures camera-to-screen latency.

5. Measure before integrating into production

Run the conversion probe on your target hardware, then evaluate the complete application's presentation age, drop behavior, UI responsiveness, and memory use with representative frames. Linux and production GPU rendering remain open work.
